    ```go
    // Kill process and clean up session directory (single path, no double-cleanup).
    if b.launcher != nil {
        b.launcher.Kill()

        if !b.opts.reusableSession && b.sessionID != "" {
            // launcher.Cleanup() removes the Chrome data dir (data/).
            b.launcher.Cleanup()
    ```

    The current behavior: when a session dir has a `scout.pid` pointing to a dead/nonexistent process, it only removes `scout.pid`. The Chrome `data/` subdir and the parent session dir are left on disk.

    Fix: after determining a session is orphaned (process dead), remove the entire session directory tree:

    ```go
    // After confirming process is dead (ProcessAlive(pid) == false):
    // Remove the full session directory including Chrome data dir.
    // Use the retry constants for Windows file lock compatibility.
    for range removeRetries {
        if err := os.RemoveAll(sessionDir); err == nil {
            break
        }
        time.Sleep(removeRetryWait)
    }
    ```

    Where `sessionDir` is the full path to `~/.scout/sessions/<id>/` (the parent, not just `data/`).

    `os.RemoveAll` on the parent removes `scout.pid`, `job.json`, `data/`, and the parent dir itself in one call — this is correct and safe.

    The `removeRetries` and `removeRetryWait` constants were added in Plan 02. They are already in scope.

    Also review `CleanStaleSessions()` — if it has its own orphan removal logic separate from `CleanOrphans()`, apply the same fix there. The goal: no function in session_track.go should leave a partial session directory after determining the owning process is dead.
